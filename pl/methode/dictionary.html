1. Przegląd

Atak słownikowy to najstarsza metoda łamania haseł, najprostsza do zrozumienia i statystycznie najskuteczniejsza wobec prawdziwych haseł wybieranych przez ludzi. Zamiast przeglądać wszystkie możliwe kombinacje jak brute force, sprawdza przygotowaną wcześniej listę kandydatów — „słownik” — w kolejności malejącego prawdopodobieństwa.

Dlaczego działa tak dobrze. Ludzie nie wybierają haseł losowo. Dziesięciolecia wycieków danych pokazują, że prawdziwe hasła są skrajnie skoncentrowane: w wycieku RockYou samego hasła 123456 używało 290 731 kont, około 2% wszystkich. Dobrze zbudowany atak słownikowy sprawdza tych kandydatów najpierw i znajduje ich w ułamku sekundy, podczas gdy brute force potrzebowałby lat.

Time2Crack korzysta z dwóch niezależnych mechanizmów:

  • Ranga słownikowa, obliczana lokalnie: czy hasło należy do najczęściej używanych haseł, być może zamaskowane leetspeakiem, albo czy jest słowem ze słownika wybranego języka? Z tej rangi wynikają czasy złamania pokazane w tabeli wyników.
  • Sprawdzenie w Have I Been Pwned (HIBP): czy dokładnie to hasło pojawiło się już w jakimś wycieku danych? Odpowiedź wyświetla się w osobnej plakietce nad wynikami.

Oba mechanizmy się uzupełniają: HIBP zna hasła, które już wyciekły, a listy słów obejmują zwykłe słowa, które jeszcze nie wyciekły.

Atak słownikowy jest starszy niż współczesne bezpieczeństwo komputerowe. Pierwsze systemy Unix przechowywały skróty haseł w pliku /etc/passwd, czytelnym dla wszystkich: każdy, kto mógł go odczytać, mógł sprawdzić listę słów na wszystkich kontach.

3. Dlaczego słowniki działają

3.1 Prawo potęgowe ludzkich haseł

Wszystkie badania empiryczne prowadzą do tego samego wniosku: hasła wybierane przez ludzi nie rozkładają się równomiernie. Podlegają prawu potęgowemu (prawu Zipfa): kilka haseł skupia nieproporcjonalnie dużą część wyborów.

Formalnie: jeśli posortujemy hasła według malejącej częstości, częstość hasła o randze r jest w przybliżeniu proporcjonalna do r−s, gdzie wykładnik s zależy od korpusu (Wang i in., 2017).

Bezpośredni skutek: atakujący, który próbuje tylko 10 najczęstszych haseł, ma już mniej więcej jedną szansę na 20 na przełamanie danego konta.

3.2 Błędy poznawcze przy tworzeniu haseł

Tworząc hasło, ludzie kierują się przewidywalnymi nawykami:

  • Łatwość zapamiętania: słowa łatwe do zapamiętania (rzeczowniki, imiona, popkultura) są nadreprezentowane.
  • Dostępność: hasło odzwierciedla najbliższe otoczenie (imię zwierzęcia, drużyna sportowa, ulubiona postać).
  • Przewidywalne zamiany: e → 3, a → @, o → 0. Użytkownik uważa hasło za silniejsze, ale to właśnie te zamiany atakujący sprawdza najpierw.
  • Dopisywanie na końcu: cyfra lub symbol na końcu słowa (password1, motyl!).
  • Język i kultura: popularne hasła zależą od języka użytkownika (Soleil123 we Francji, Sommer123 w Niemczech).

3.3 Dwa sposoby, by znaleźć się „na listach”

Hasło może trafić na listę atakującego z dwóch różnych powodów:

  • Już wyciekło. Dokładnie to hasło pojawiło się w dawnym wycieku. Atakujący nie musi zgadywać: sprawdza znane hasła w kolejności częstości.
  • To zwykłe słowo. Nawet jeśli nigdy nie wyciekło, jest na każdej liście atakującego, bo to oczywisty kandydat. Słowo takie jak parasol może nie występować w HIBP, ale jest na polskiej liście każdego poważnego narzędzia do łamania haseł.

Ta różnica około sześciu rzędów wielkości między MD5 a bcrypt pokazuje, jak ważny jest wybór algorytmu skrótu.

5. Korpusy prawdziwych haseł

5.1 Have I Been Pwned (HIBP)

  • Rozmiar: ponad miliard różnych haseł z ponad 14 miliardów przejętych kont
  • Źródło: zbiór publicznych wycieków od 2013 roku

6. Sprawdzanie w HIBP (k-anonimowość)

6.1 Protokół k-anonimowości

Time2Crack sprawdza hasło w HIBP, nigdy go nie wysyłając — ani hasła, ani jego pełnego skrótu. Protokół działa tak:

1. Obliczyć SHA-1(hasło)
     → np. CBFDAC6008F9CAB4083784CBD1874F76618D2A97
2. Wysłać do API HIBP tylko pierwsze 5 znaków
     → GET https://api.pwnedpasswords.com/range/CBFDA
3. API zwraca wszystkie końcówki skrótów zaczynające się od tego prefiksu
     (kilkaset wierszy, uzupełnionych fałszywymi wpisami)
4. Lokalnie poszukać w odpowiedzi reszty skrótu
     → C6008F9CAB4083784CBD1874F76618D2A97
5. Znaleziono: hasło wyciekło, a HIBP podaje, ile razy
   Nie znaleziono: hasła nie ma w HIBP

Gwarancja prywatności: serwer HIBP widzi tylko 5-znakowy prefiks wspólny dla setek haseł. Nie może wiedzieć, które hasło sprawdzono. Porównanie odbywa się w przeglądarce.

6.2 Implementacja w Time2Crack

Sprawdzanie rusza pół sekundy po ostatnim naciśnięciu klawisza, równolegle z analizą lokalną:

// app.js - checkHIBP()
async function checkHIBP(password) {
  const sha1 = await sha1Hex(password);   // uppercase hex SHA-1
  const prefix = sha1.slice(0, 5);        // sent to the API
  const suffix = sha1.slice(5);           // never leaves the browser

  const res = await fetch(`https://api.pwnedpasswords.com/range/${prefix}`, {
    headers: { "Add-Padding": "true" },   // hide the real size of the response
  });
  if (!res.ok) return null;               // API unavailable

  const text = await res.text();
  for (const line of text.split("\n")) {
    const [hashSuffix, count] = line.trim().split(":");
    if (hashSuffix === suffix) return parseInt(count, 10); // number of leaks
  }
  return 0;                               // not found
}

Wynik pojawia się w plakietce: „znaleziono N razy”, „nie znaleziono” albo „niedostępne”, gdy API nie odpowiada. Nie zmienia czasów złamania, które są obliczane lokalnie.

7.2 Wczytywanie na żądanie

Listy słów nie są dołączone do kodu. Pobierana jest tylko lista wybranego języka, w chwili, gdy jest po raz pierwszy potrzebna, jako plik gzip:

// app.js - loadDictionary() (simplified: progress bar updates removed)
async function loadDictionary(lang = AppConfig.lang) {
  // Already loaded for this language
  if (AppConfig.dictWords !== null && AppConfig.dictLang === lang) return;

  // 1. Local cache (IndexedDB)
  const cached = await cacheGet(`dict_${lang}`);
  if (cached) {
    AppConfig.setDictionary(new Set(cached), lang);
    return;
  }

  // 2. Download the compressed list
  const res = await fetch(`${basePath}data/wordlists/${lang}.txt.gz`);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  const buffer = await res.arrayBuffer();

  // 3. Decompress in the browser (plain .txt if DecompressionStream is missing)
  let text;
  try {
    text = await new Response(
      ReadableStream.from([new Uint8Array(buffer)])
        .pipeThrough(new DecompressionStream("gzip"))
    ).text();
  } catch {
    text = await (await fetch(`${basePath}data/wordlists/${lang}.txt`)).text();
  }

  // 4. Normalise, filter, index
  const words = text.split("\n")
    .map(w => w.trim().toLowerCase())
    .filter(w => w.length >= 3);
  AppConfig.setDictionary(new Set(words), lang);

  // 5. Keep it for the next visit
  await cachePut(`dict_${lang}`, words);
}

Dlaczego Set? Set w JavaScripcie odpowiada na dictWords.has(word) w stałym czasie, niezależnie od tego, czy lista ma 285 000 słów (hiszpański), czy 3,7 miliona (polski). Przy Array każde wyszukiwanie mogłoby wymagać jednego porównania na słowo.

8. Ranga słownikowa: rankDictionary()

8.1 Zasada: najpierw ranga, potem czas

Time2Crack nie pyta tylko „czy to słowo ze słownika?”, ale „po ilu próbach znalazłby je atak słownikowy?”. Ta liczba prób to ranga. Funkcja rankDictionary() (plik core/rank/dictionary.js) zwraca ją albo zwraca null, gdy atak nie ma zastosowania:

// core/rank/dictionary.js - rankDictionary()
export function rankDictionary(password, dictWords = null) {
  const lower = password.toLowerCase();
  const deleeted = deleet(password);
  const alpha = password.replace(/[^a-zA-Z]/g, "");
  const uCost = uppercaseCost(alpha);        // capital letters, see 8.3

  // 1. In the top passwords as is?
  const topIdx = TOP_PASSWORDS.indexOf(lower);
  if (topIdx !== -1) return { rank: (topIdx + 1) * uCost, model: "dictionary" };

  // 2. De-leeted form in the top passwords?
  const deIdx = TOP_PASSWORDS.indexOf(deleeted);
  if (deIdx !== -1) return { rank: (deIdx + 1) * 10 * uCost, model: "dictionary" };

  // 3. In the wordlist of the selected language?
  if (dictWords instanceof Set) {
    if (dictWords.has(lower) || dictWords.has(deleeted)) {
      const mid = Math.floor(dictWords.size / 2);
      if (passwordLength(password) >= 9) {
        // a long word may also be split into shorter words, see 8.4
        const compound = rankGermanCompound(password, dictWords);
        if (compound && compound.rank < mid)
          return { rank: compound.rank * uCost, model: "dictionary" };
      }
      return { rank: mid * uCost, model: "dictionary" };
    }

    // 4. Compound made of several dictionary words?
    const compound = rankGermanCompound(password, dictWords);
    if (compound) return { rank: compound.rank * uCost, model: "dictionary" };
  }

  // Not found: the dictionary attack does not apply
  return { rank: null, model: "dictionary" };
}

Niemiecki (i niderlandzki) łączy słowa w jedno: Apfelbaumkuchen = Apfel + Baum + Kuchen. Takiego słowa często nie ma na liście, ale atakujący może je zbudować z krótszych słów. Time2Crack próbuje podzielić hasło na 2–4 słowa z listy, dopuszczając zwykłe niemieckie łączniki (-s-, -es-, -n-, -en-, -er-, -e-). Ranga to wtedy ranga maskowa hasła pomnożona przez 0,25 (2 słowa), 0,16 (3 słowa) lub 0,10 (4 słowa) oraz przez 0,75, gdy ostatni fragment to popularny przyrostek (-heit, -ung, -haus…).

Podział jest też sprawdzany dla długich słów, które są na liście (9 znaków lub więcej), i zachowywany, jeśli daje niższą rangę: Sonnenblume otrzymuje rangę 42 680 zamiast połowy listy niemieckiej (1 004 940).

9. Odwracanie leetspeaku

9.1 Leetspeak nie chroni

Leetspeak zastępuje litery podobnie wyglądającymi cyframi lub symbolami: a → @, e → 3, i → 1, o → 0, s → $. Ludzie używają go, by „wzmocnić” zwykłe słowo: password → p@$$w0rd.

W rzeczywistości te zamiany należą do pierwszych reguł stosowanych przez narzędzia do łamania haseł. Nie spowalniają kompetentnego atakującego.

9.2 Funkcja deleet()

// core/rank/dictionary.js - deleet()
function deleet(pw) {
  return pw
    .toLowerCase()
    .replace(/0/g, "o")
    .replace(/1/g, "i")
    .replace(/3/g, "e")
    .replace(/4/g, "a")
    .replace(/5/g, "s")
    .replace(/7/g, "t")
    .replace(/8/g, "b")
    .replace(/@/g, "a")
    .replace(/\$/g, "s")
    .replace(/!/g, "i");
}

Hasło jest wyszukiwane zarówno w postaci wpisanej, jak i po odwróceniu leetspeaku. Wśród najczęstszych haseł forma po odwróceniu kosztuje 10 razy więcej (atakujący musi wypróbować warianty): p@ssw0rd → 20 zamiast 2. Na liście językowej kosztuje tyle samo co zwykłe słowo.

9.3 Czego nie odkodowujemy

  • Każdy znak ma tylko jeden zamiennik: 1 zawsze staje się i, nigdy l; dlatego p1ayer nie zostaje rozpoznane jako player.
  • Rzadsze zamiany (+ → t, 9 → g, # → h) nie są odkodowywane.
  • Słowo, po którym następują cyfry lub symbole (motyl2024, motyl!), nie jest trafieniem słownikowym: zajmuje się nim atak hybrydowy.

10. Od rangi do czasu złamania

Rangę przelicza się na sekundy, dzieląc ją przez prędkość obliczania skrótów przez atakującego:

// core/time.js - rankToSeconds()
export function rankToSeconds(rank, algo, profile = "experienced") {
  const baseRate = HASH_RATES[algo];   // guesses per second, 12× RTX 5090
  if (!baseRate) throw new Error(`Unknown algorithm: ${algo}`);
  const multiplier = ATTACKER_MULTIPLIERS[profile] ?? 1;
  return rank / (baseRate * multiplier);
}

Przykład dla soleil (lista francuska, ranga 275 117) z profilem domyślnym:

MD52 634 GH/s275 117 / 2 634 × 109104 nanosekund

SHA-256332 GH/s275 117 / 332 × 109829 nanosekund
bcrypt (koszt 5)3 658 kH/s275 117 / 3 658 0000,08 sekundy

Nawet przy Argon2id zwykłe francuskie słowo pada w niecałe 5 minut. Profil atakującego zmienia prędkości: od jednego GPU (profil „Amateur”) do około 10 000 GPU (profil „Państwo”). Jak w przypadku wszystkich innych modeli, ranga słownikowa nigdy nie może przekroczyć rangi brute force dla tego samego hasła.

11. Porównanie z atakami pochodnymi

„Czysty” atak słownikowy to pierwszy z rodziny ataków, które wszystkie wychodzą od listy słów. Time2Crack oblicza dziewięć modeli (brute force, słownik, hybryda, maska, PCFG, Markov, kombinator, wzorce klawiatury, daty), z których każdy atakuje hasło z innej strony.

11.1 Słownik a hybryda

KryteriumSłownikHybryda (słownik + reguły)
KandydaciSłowa z listy, bez zmianKażde słowo z przekształceniami (cyfry, symbole, wielkie litery…)
Złamane przykładypassword, motylP@ssw0rd!, motyl2024
PrędkośćMniej kandydatów, więc szybciejZnacznie szersze pokrycie
Ma zastosowanie, gdyDokładne słowo jest na liścieHasło pochodzi od słowa z listy

Atak hybrydowy zaczyna się tam, gdzie kończy się czysty słownik: stosuje systematyczne reguły przekształceń do każdego słowa z listy (w duchu best64.rule z hashcata).

11.2 Słownik a PCFG

KryteriumSłownikPCFG
ModelStała lista kandydatówProbabilistyczna gramatyka struktur haseł
Mocna stronaDokładne słowaStruktury takie jak słowo + cyfry, wielka litera + małe + symbol
Przykładpassword ✓Password123 ✓ (rozpoznana struktura)

Password123 samo w sobie nie jest słowem ze słownika, ale PCFG rozpoznaje jego strukturę [wielka litera][małe litery][cyfry] i łamie je bardzo szybko.

11.3 Słownik a Markov

KryteriumSłownikMarkov
KandydaciLista przygotowana z góryGenerowani na bieżąco przez model statystyczny
PokrycieZnane słownictwoKażdy ciąg, który „wygląda po ludzku”
ZaletaBardzo szybki dla dokładnych słówObejmuje też słowa nieobecne na listach

Markov obejmuje hasła, które przypominają ludzkie słowa, choć nie ma ich na żadnej liście.

11.4 Słownik a credential stuffing

KryteriumSłownikCredential stuffing
CelZłamać skrótZalogować się na konto
MechanizmLokalne obliczanie skrótówZdalne próby logowania
ŹródłoOgólna lista słówPary e-mail/hasło z wycieków
ObronaWolny algorytm skrótuOgraniczanie prób, MFA, blokowanie IP

Credential stuffing nie atakuje skrótu: wypróbowuje pary e-mail/hasło z wycieków bezpośrednio w usługach internetowych. To inny atak, ale korzysta z tych samych danych (wycieków takich jak te zindeksowane w HIBP). Time2Crack go nie modeluje.

12. Ograniczenia ataku słownikowego

12.1 Ograniczenia wewnętrzne

  • Tylko znane słownictwo. Wymyślone hasło, które nie przypomina żadnego istniejącego słowa i nigdy nie wyciekło, wymyka się czystemu atakowi słownikowemu: Xqz7mK9pL nie ma na żadnej liście.
  • Pokrycie językowe. Atakujący, który celuje w polskojęzycznych użytkowników bez polskiej listy, przeoczy słowa takie jak parasol czy słonecznik.
  • Nowe hasła. Hasła, które nigdy nie wyciekło, nie ma w HIBP, nawet jeśli jest popularne.
  • Długie frazy. MojaWielkaPrzygodaPodGwiazdami nie ma na żadnej liście, choć każde słowo jest banalne. Frazami hasłowymi zajmują się inne ataki (kombinator, PRINCE).

12.2 Czego Time2Crack nie modeluje

  • Listy celowane: atakujący, który celuje w konkretną branżę, buduje własne listy (terminy medyczne dla szpitala, slang graczy dla platformy z grami). Narzędzia takie jak CeWL wyciągają słowa ze strony internetowej celu. Time2Crack używa list ogólnych.
  • Świeże wycieki: między wyciekiem a jego dodaniem do HIBP hasła krążą prywatnie i nie są widoczne przez publiczne API.
  • Inne algorytmy skrótu: Time2Crack modeluje sześć algorytmów (MD5, SHA-1, SHA-256, NTLM, bcrypt, Argon2id). SHA-512, scrypt czy PBKDF2 mają inne profile.
  • Częstość słów: każde słowo z listy językowej dostaje tę samą rangę (połowę listy), niezależnie od tego, czy jest bardzo popularne, czy bardzo rzadkie.

13. Skuteczna obrona

13.1 Co chroni

Wolny algorytm skrótu (bcrypt, Argon2id). To najskuteczniejsza obrona po stronie serwera: każda próba kosztuje więcej. Dla soleil (ranga 275 117):

  • MD5: około 0,1 mikrosekundy
  • bcrypt koszt 12 (128 razy wolniej niż koszt 5): około 10 sekund
  • Argon2id: około 5 minut

Wolny skrót spowalnia atakującego, ale nie ratuje słowa ze słownika: lista jest po prostu za krótka.

Unikalna sól dla każdego konta. Sprawia, że tablice obliczone z góry (tęczowe tablice) są bezużyteczne, i zmusza atakującego do pracy konto po koncie. Nie zapobiega atakowi listą słów na pojedyncze konto.

Długość i losowość. Pojedyncze słowo ze słownika jest zawsze podatne. Fraza z 4 lub 5 słów opiera się czystemu atakowi słownikowemu, ale nie atakowi kombinatorowemu, jeśli słowa są przewidywalne: trzeba je wylosować.

Losowo generowane hasła. Prawdziwe rozwiązanie: menedżer haseł, który generuje długie losowe hasła (20 znaków lub więcej). Nie ma ich w żadnym słowniku.

Uwierzytelnianie wieloskładnikowe (MFA). Nie zapobiega łamaniu offline wykradzionych skrótów, ale nie pozwala atakującemu zalogować się złamanym hasłem.

Ograniczanie prób i wykrywanie anomalii. Chronią przed próbami online, nie przed łamaniem offline wykradzionych skrótów.

13.2 Co nie chroni

  • Zamiany w leetspeaku: password → p@ssw0rd (zob. rozdział 9).
  • Cyfra na końcu: password → password1, jedna z pierwszych sprawdzanych reguł.
  • Wielka pierwsza litera: password → Password, standardowa reguła (ranga × 2).
  • Cyfry i symbole wokół rozpoznawalnego słowa: motyl! zostaje znalezione najprostszymi regułami.
  • Złożoność bez długości: P@s1w spełnia typowe wymogi (wielka i mała litera, cyfra, symbol), ale jest krótsze i bardziej przewidywalne niż correcthorsebatterystaple.

13.3 Praktyczne zalecenia

  • Używaj menedżera haseł (Bitwarden, 1Password, KeePass): generuje losowe hasła, a ty pamiętasz tylko hasło główne.
  • Włącz MFA wszędzie: nawet jeśli hasło wycieknie, atakujący się nie zaloguje.
  • Regularnie sprawdzaj HIBP, aby wiedzieć, czy twój adres e-mail występuje w znanych wyciekach.
  • Nigdy nie używaj ponownie tego samego hasła: credential stuffing wykorzystuje powtarzanie haseł w różnych usługach.
  • Dla haseł, które musisz pamiętać: fraza z 5 lub więcej słów, wylosowanych (kośćmi albo generatorem), a nie wybranych.
